# app_link — phone GPS over Wi-Fi

Browsers only expose `navigator.geolocation` on HTTPS (secure context), so the
board serves the phone page itself over HTTPS:

- softAP `飞行表-XXXX` (WPA2, 8-digit password generated once, NVS `pfd/ap_pass`),
  IP 192.168.4.1. No DNS server on purpose (avoids the captive-portal mini
  browser, which cannot use geolocation).
- Optional station uplink: page form (NVS `pfd/sta_ssid`,`sta_pass`) or, if
  none, the Wi-Fi already stored on the device by the ESP-Mosaico system (read-only). 3
  attempts, then gives up until reboot / new settings. "不再连接" sets `sta_off`.
- HTTPS :443 (`certs/`, git-ignored, generated by `tools/gen_cert.sh` on the first
  CMake configure if missing: P-256 leaf for 192.168.4.1
  + 172.20.10.2-14 signed by a name-constrained local CA whose key is destroyed).
  HTTP :80 only redirects. Endpoints: `/` page, `POST /api/gps`, `GET /api/info`,
  `POST /api/wifi`, `/ca.crt` (iOS profile).
- Uses POST (fetch) instead of WebSocket: iOS Safari refuses `wss://` to a
  self-signed host even after the page warning was accepted.
- Link timeout 3 s → "信号丢失". Speed: browser `coords.speed`, else derived
  from successive fixes. Wi-Fi/lwIP/httpd pinned to core 1 below the IMU task.
- Host: `link_host.c` (PFD_HOST_GPS=1|lost). Tests: `tests/host/test_link.c`.
